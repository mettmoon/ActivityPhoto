# Geoshop 기획서

- 버전: v0.2
- 작성일: 2026-11-12
- 상태: 의사결정 완료 (§2). 개발 착수 가능
- 앱 이름: **Geoshop** (Xcode 프로젝트/타깃 이름은 `ActivityPhoto` 유지, 표시 이름만 Geoshop)

---

## 1. 개요

### 1.1 한 줄 정의
GPX 트랙을 기준으로 사진의 **촬영일시**와 **위치**를 지도·고도표에서 골라 일괄로 바꿔 주는 Mac 앱.

### 1.2 해결하려는 문제
- 카메라 시계가 틀렸거나, 메신저·스캔 등으로 촬영 정보가 사라진 사진이 많다.
- GPS가 없는 카메라로 찍은 활동(등산, 라이딩, 트레킹) 사진에 위치가 없다.
- 사진 앱의 "날짜/위치 조정"은 한 장씩 손으로 입력해야 해서, 기록해 둔 GPX 경로를 활용할 수 없다.

### 1.3 핵심 흐름
1. GPX 파일을 넣어 **프로젝트 생성**
2. 편집할 **사진을 프로젝트에 추가** (원본은 참조만 저장)
3. 사진을 선택하고 **지도나 고도표에서 지점을 클릭**하면 그 지점의 시각과 위치가 사진에 **임시 할당**
4. **일괄 적용**을 누르면 할당된 값이 사진에 실제로 반영

## 2. 확정된 의사결정

| # | 항목 | 결정 | 비고 |
|---|------|------|------|
| D1 | 타겟 플랫폼 | **macOS 우선** | SwiftUI로 작성해 iPad 확장 여지 유지. visionOS 등 기타 플랫폼은 v1 대상 아님 |

| D3 | 보관함 반영 방식 | **보관함 메타데이터만 변경** | 사진 앱의 "날짜/위치 조정"과 같은 방식. 원본 파일은 건드리지 않음 |
| D4 | 시간대 | **GPX 위치로 자동 판별 + 프로젝트 설정에서 수정 가능** | 파일 소스는 `OffsetTimeOriginal`도 기록 |
| D5 | 다중 선택 할당 | **선택한 모든 사진에 같은 지점(같은 시각·위치) 할당** | 시각 분산, 간격 배분 없음 |
| D6 | 자동 매칭 | **넣지 않음 (수동 선택만)** | 사진의 기존 촬영시각은 참고용으로 표시만 |
| D7 | 파일 쓰기 | **원본 파일에 바로 덮어쓰기** | 백업 없음. 이미지 재압축 없이 메타데이터만 교체. 적용 전 확인 단계 필수 |
| D8 | GPX 개수 | **프로젝트당 여러 개 허용** | 멀티데이 활동 대응. 생성 시 최소 1개 필수 |
| D9 | 트랙이 겹치는 곳 클릭 | **후보 팝오버에서 선택** | 후보가 하나면 바로 할당 (§4.3) |
| D10 | 여러 시간대에 걸친 GPX | **프로젝트당 시간대 1개** | 시간대가 다르면 프로젝트를 나눠 쓰도록 안내 |
| D11 | 같은 지점 다중 할당 시 시각 | **완전히 같은 시각 그대로** | 사진 앱 등에서 순서가 보장되지 않음을 감수 |
| D12 | `DateTimeDigitized` | **`DateTimeOriginal`과 같은 값으로 변경** | 오프셋(`OffsetTimeDigitized`)도 함께 |
| D13 | 덮어쓰기 안전장치 | **프로젝트 첫 적용 시 1회 동의** + 매번 확인 시트 | 파일 소스 프로젝트만 해당 |
| D14 | 배포 | **Mac App Store** | App Sandbox 필수. 현재 설계(보안 범위 북마크)와 맞음 |

## 3. 용어

| 용어 | 정의 |
|------|------|
| 프로젝트 | GPX 트랙 1개 이상 + 참조 사진 목록 + 할당 정보 + 설정(소스 종류, 시간대)의 묶음 |
| 트랙 포인트 | GPX `<trkpt>`. 위도·경도·고도(선택)·시각(필수) |
| 할당 (Assignment) | 사진에 임시로 기억해 둔 "적용할 시각 + 위치(+고도)". 일괄 적용 전까지는 앱 안에만 존재 |
| 적용 (Apply) | 할당 값을 실제 사진(보관함 메타데이터 또는 파일 EXIF)에 쓰는 동작 |

## 4. 기능 명세

### 4.1 프로젝트 생성
- 입력 항목
  - 이름 (기본값: 첫 GPX의 `<name>` 또는 파일명)
  - GPX 파일 1개 이상 (**필수**)
  - 사진 소스: `사진 앱 보관함` / `파일` (**필수**, 이후 변경 불가)
- GPX 처리
  - 파일은 앱 컨테이너로 **복사**해서 보관한다. 원본 GPX를 옮기거나 지워도 프로젝트가 깨지지 않게 하기 위함 (사진과 달리 GPX는 작고, 프로젝트의 기준 데이터이므로 복사).
  - `<trk>/<trkseg>/<trkpt>`만 사용. `<wpt>`, `<rte>`는 v1에서 무시.
  - **시각이 없는 트랙 포인트만 있는 GPX는 거부**하고 이유를 안내 (시간 정보 없이는 촬영일시를 정할 수 없음).
  - 시각이 일부만 빠진 포인트는 버린다.
- 시간대 자동 판별 (D4, D10)
  - 첫 GPX의 시작 좌표를 역지오코딩해 시간대를 얻는다. 프로젝트 전체에 이 시간대 하나만 쓴다.
  - 네트워크 실패 시 기기 시간대로 대체하고, 프로젝트 화면에 "시간대 확인 필요" 표시.
  - GPX를 추가할 때 그 시작 좌표의 시간대(UTC 오프셋)가 프로젝트 시간대와 다르면 경고한다: "이 트랙은 다른 시간대입니다. 파일 소스라면 촬영일시가 프로젝트 시간대로 기록됩니다. 별도 프로젝트로 나누는 것을 권장합니다." 추가 자체는 막지 않는다.
- 프로젝트 화면에서 나중에 GPX를 더 추가하거나 뺄 수 있다 (마지막 1개는 삭제 불가).

### 4.2 사진 추가 (참조만 저장)
| 소스 | 추가 방법 | 저장하는 참조 | 비고 |
|------|----------|--------------|------|
| 사진 앱 보관함 | 사진 선택기 | `PHAsset.localIdentifier` | 보관함 읽기/쓰기 전체 권한 필요 |
| 파일 | 파일 열기 패널(다중 선택, 폴더 선택 시 하위 이미지 일괄) 또는 드래그 앤 드롭 | 보안 범위 북마크 (app-scope) | 같은 볼륨 내 이동은 북마크가 따라감 |

- 같은 사진 중복 추가는 무시한다.
- 추가 시 사진의 현재 촬영일시·위치를 읽어 **참고 정보**로 표시 (D6: 자동 할당은 하지 않음).
- 지원 형식 (v1)
  - 보관함: 사진(Live Photo 포함). 동영상은 v1 제외.
  - 파일: JPEG, HEIC/HEIF, PNG, TIFF. RAW(CR3, NEF, ARW 등)와 DNG는 v1 제외하고 "지원하지 않는 형식"으로 표시.
- 보관함 사진 중 편집할 수 없는 것(공유 앨범 등, `canPerform(.properties) == false`)은 추가는 되지만 "편집 불가" 상태로 표시.

### 4.3 할당 (지도·고도표에서 지점 선택)
- **사진 선택**: 그리드에서 클릭 / ⌘·⇧ 클릭으로 다중 선택.
- **지점 선택**
  - 지도: 클릭한 좌표에서 가장 가까운 트랙 위의 점으로 **스냅**. 화면상 일정 거리(약 30pt) 밖이면 무시.
  - 고도표: 클릭한 x 위치에 해당하는 트랙 위의 점. 고도표에서는 지점이 하나로 정해진다.
  - 두 트랙 포인트 사이 지점은 시각·좌표·고도를 **선형 보간**.
- **겹치는 구간 처리 (D9)**: 왕복 코스나 같은 길을 여러 번 지난 경우
  - 스냅 반경 안에서 트랙 세그먼트별로 가장 가까운 점을 모은다.
  - 시각이 **5분 이상** 떨어진 후보가 2개 이상이면, 클릭한 곳에 후보 팝오버를 띄운다. 각 후보는 `시각 · 고도 · 누적거리 · 트랙 이름`을 보여 준다. 후보에 마우스를 올리면 고도표에 그 위치를 표시한다.
  - 5분 안에 모인 후보들은 하나로 보고 가장 가까운 점을 쓴다.
  - 후보가 하나면 팝오버 없이 바로 할당한다.
  - Esc 또는 팝오버 밖 클릭은 취소.
- **할당 결과**: 선택된 모든 사진에 완전히 같은 시각·위치·고도 (D5, D11). 촬영시각이 같아지므로 다른 앱에서 순서가 섞일 수 있다.
- **지도↔고도표 연동**: 한쪽에 마우스를 올리면 다른 쪽에 같은 지점의 커서를 표시하고, 시각·고도·누적거리를 툴팁으로 보여 준다.
- 할당 해제: 사진 선택 후 "할당 해제" (Delete 키).
- 실행 취소: 할당/해제는 ⌘Z / ⇧⌘Z 지원.
- 이미 적용한 사진을 다시 할당하면 상태가 "할당됨(대기)"으로 돌아간다.

### 4.4 일괄 적용
1. 툴바의 **일괄 적용 (N)** 버튼. N = 대기 중인 할당 수. 0이면 비활성.
2. **확인 시트**: 사진별 변경 전/후(촬영일시, 위치) 목록. 파일 소스면 "원본 파일을 직접 수정하며 되돌릴 수 없습니다" 경고 (D7).
   - 파일 소스 프로젝트의 **첫 적용**에서는 "원본 파일이 덮어써지며 되돌릴 수 없음을 이해했습니다" 체크박스를 켜야 적용 버튼이 활성화된다 (D13). 동의는 프로젝트에 저장되고, 이후 적용에서는 경고 문구만 표시한다.
3. 진행률 표시, 취소 가능 (이미 끝난 사진은 유지).
4. 결과 요약: 성공 / 실패(사유) 개수. 실패한 사진은 할당 상태를 유지해서 다시 시도할 수 있음.

#### 4.4.1 보관함 소스 (D3)
- `PHAssetChangeRequest`로 아래 두 값을 변경:
  - `creationDate` ← 할당된 시각 (절대 시각)
  - `location` ← `CLLocation(좌표, 고도, timestamp: 할당 시각)`
- 여러 장을 한 번의 변경 요청 묶음으로 처리.
- 원본 파일 EXIF는 그대로라서, 사진 앱에서 "수정되지 않은 원본"으로 내보내면 옛 값이 나온다. 일반 내보내기에는 변경된 값이 반영된다 (도움말에 안내).
- 보관함 사진은 시간대를 따로 쓸 수 없다. 시간대 설정은 화면 표시용으로만 쓰인다.

#### 4.4.2 파일 소스 (D7)
- ImageIO로 **이미지 데이터는 재압축 없이** 메타데이터만 교체해 원본 경로에 덮어쓴다 (임시 파일에 쓴 뒤 교체해서 중간 실패 시 원본이 깨지지 않게 함).
- 기록하는 필드:

| 영역 | 필드 | 값 |
|------|------|----|
| EXIF | `DateTimeOriginal`, `DateTimeDigitized` | 둘 다 같은 값 (D12). 프로젝트 시간대 기준 현지 시각 `yyyy:MM:dd HH:mm:ss` |
| EXIF | `OffsetTimeOriginal`, `OffsetTimeDigitized` | 예: `+09:00` |
| TIFF | `DateTime` | 건드리지 않음 (수정 시각 의미이므로) |
| GPS | `GPSLatitude`/`Ref`, `GPSLongitude`/`Ref` | 할당 좌표 |
| GPS | `GPSAltitude`/`Ref` | GPX `<ele>`가 있을 때만 |
| GPS | `GPSDateStamp`, `GPSTimeStamp` | 할당 시각 (UTC) |

- 파일 시스템의 생성/수정일은 변경하지 않는다.

### 4.5 사진 상태

| 상태 | 표시 | 설명 |
|------|------|------|
| 미할당 | 배지 없음 | |
| 할당됨(대기) | 주황 점 | 일괄 적용 대상 |
| 적용됨 | 초록 체크 | 마지막 적용 값과 할당이 같음 |
| 실패 | 빨간 느낌표 | 사유는 툴팁 |

- 고도표 x축 기본은 **누적 거리**. 여러 GPX는 시각 순으로 이어 붙이고, 트랙 사이 공백은 끊어서 그린다. 시간 축 모드에서는 공백 구간이 빈칸으로 보인다.

## 6. 데이터 모델 (SwiftData 초안)

```swift
@Model final class Project {
    var name: String
    var sourceKind: SourceKind        // .photoLibrary | .files  (생성 후 불변)
    var timeZoneID: String            // 예: "Asia/Seoul"
    var timeZoneIsAuto: Bool
    var overwriteConsentGiven: Bool   // 파일 소스 첫 적용 동의 (D13)
    var createdAt: Date
    @Relationship(deleteRule: .cascade) var tracks: [TrackFile]
    @Relationship(deleteRule: .cascade) var photos: [PhotoRef]
}

@Model final class TrackFile {
    var displayName: String
    var storedFileName: String        // 앱 컨테이너에 복사한 GPX
    var colorIndex: Int
    var startTime: Date
    var endTime: Date
}

@Model final class PhotoRef {
    var assetIdentifier: String?      // 보관함 소스
    var bookmarkData: Data?           // 파일 소스
    var addedAt: Date
    var originalDate: Date?           // 추가 시점에 읽은 기존 값 (참고용)
    var originalLatitude: Double?
    var originalLongitude: Double?
    var assignment: Assignment?       // 임시 할당 (Codable 값 타입)
    var appliedAssignment: Assignment?
    var lastError: String?
}

struct Assignment: Codable, Equatable {
    var date: Date                    // 절대 시각 (UTC)
    var latitude: Double
    var longitude: Double
    var altitude: Double?
}
```

- 파싱한 트랙 포인트는 DB에 넣지 않고 프로젝트를 열 때 GPX에서 읽어 메모리에 둔다.
- 상태(§4.5)는 `assignment`, `appliedAssignment`, `lastError`와 참조 해석 결과로 계산.
